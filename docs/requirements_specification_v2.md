# Desktop Avatar Platform 要件定義書 (v2)

## 1. プロジェクト概要
本作は、単一のLive2Dモデル表示アプリに留まらない、**拡張可能な汎用デスクトップアバター基盤**である。
マウス、カメラ、音声など多様な入力を統合し、アバターの実装方式（Live2D等）に依存しない構造を提供することで、次世代のデスクトップマスコット体験を実現する。

## 2. コアミッション
- **抽象化**: 入力ソースとアバター実装を完全に分離し、プラグイン感覚で拡張可能にする。
- **統合制御**: 複数の入力（カメラ優先、不在時はカーソル等）を賢く統合し、自然な振る舞いを生成する。
- **マスコット性**: 透明ウィンドウ、常に手前に表示、ドラッグ移動などのデスクトップ統合機能をネイティブに提供する。

## 3. 機能要件

### 3.1 入力レイヤー (Input Layer)
- **カーソル追従**: マウスカーソルの座標を取得し、視線データに変換する。
- **ドラッグ/クリック**: キャラクターへの直接的な操作（ウィンドウ移動、部位クリック）を検知する。
- **拡張性**: 将来的にカメラ（顔認識）や音声（リップシンク）の入力を同一インターフェースで追加可能であること。

### 3.2 制御レイヤー (Control Layer)
- **AvatarState 生成**: 多様な入力を統合し、単一の「アバターの状態（視線、表情、口の開閉）」を生成する。
- **優先順位管理**: カメラ入力が有効な場合はカメラを優先し、無効時はカーソルにフォールバックする等の論理制御。
- **モーション管理**: モーションの再生要求、キューイング、割り込み、優先度制御。

### 3.3 アバターレイヤー (Adapter Layer)
- **モデル描画**: 抽象化された「AvatarState」を受け取り、実際のアバター（Live2D等）に反映・描画する。
- **依存の遮断**: アバター実装側は入力を直接参照せず、渡された状態を描画することに専念する。

## 4. デスクトップ統合要件
- **ウィンドウ移動**: モデルのドラッグによりウィンドウ自体が移動すること。
- **部位判定**: モデルの特定部位（頭、体など）のクリックを判定し、制御レイヤーへ通知すること。
- **モデル管理**: 設定ファイル（settings.json）経由で、複数のモデルを動的に切り替え可能であること。

## 5. 非機能要件
- **非同期前提**: 入力データの欠損や停止に対し、スムージングやキャッシュを用いて自然な挙動を維持すること。
- **プロセス分離**: 重い処理（描画・入力解釈）はレンダラーで行い、OS操作（ウィンドウ移動・透過）はメインプロセスで行う。
